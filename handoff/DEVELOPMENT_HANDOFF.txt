PRODUCT AND PLATFORM CONSTRAINTS

- This is a native SwiftUI iOS/iPadOS application, not Android Studio, Flutter, React Native, or a web wrapper.
- A Mac with Xcode is required for the final signed device build. The current Windows environment can implement and run Go tests, while GitHub's macOS runner verifies the iOS project.
- The user will eventually install the app through Xcode using an Apple ID/development team. A free Apple developer account can sign a personal device build but has provisioning limitations and typically requires periodic re-signing; App Store/TestFlight distribution requires the appropriate paid Apple program.
- The app cannot arbitrarily browse another app's private sandbox. It uses the system document picker and a persisted security-scoped bookmark to access the user-selected Obsidian vault exposed through the Files provider.
- Sync runs only while the app is in the foreground. If the scene stops being active, cancel the session and release the security-scoped resource. Do not claim reliable background synchronization.
- The app should use a manual workflow: open Vault Sync, start sync, keep it open until both sides are verified current, let the embedded engine stop and release access, then return to Obsidian.
- Network access is direct Syncthing protocol. The embedded configuration currently uses TCP. QUIC, NAT traversal, and STUN were intentionally excluded from the current iOS-safe build. Discovery and relays are supported where currently configured.
- Never store Syncthing engine state or certificates in the synchronized vault. Store them in the application's Application Support directory.
- Never put raw absolute vault paths, device IDs, peer labels, addresses, keys, or raw internal errors into exported diagnostics.

CURRENT ARCHITECTURE

Go core:

- core/mobilecore is a thin gomobile-bindable API around Syncthing v2.1.1.
- client.go serializes engine lifecycle and exposes primitive/string APIs safe for gomobile.
- syncthing_engine.go owns Syncthing application construction, identity, lifecycle, event logger, configuration wrapper, and service goroutines.
- configuration.go configures a peer and one send/receive folder and explicitly requests scans.
- status.go exposes a versioned JSON snapshot used by Swift to decide when both sides are genuinely up to date.
- transfer_integration_test.go starts two independent Syncthing processes and proves exact bidirectional content transfer.
- build-core-xcframework.sh cross-compiles the core into Mobilecore.xcframework for device and simulator architectures.

Swift application:

- SyncthingBridge.swift wraps the gomobile-generated Mobilecore API and decodes versioned JSON.
- VaultBookmarkStore.swift persists a versioned bookmark record under Application Support/VaultSync.
- VaultAccessCoordinator.swift resolves the bookmark, starts security-scoped access, refreshes stale bookmarks, and releases access through VaultAccessSession.
- SyncProfile.swift and SyncProfileManager.swift persist and validate the remote device/folder configuration.
- SyncSessionController.swift owns the foreground session state machine, cancellation, stable completion sampling, safe engine stop, conflict scan, and diagnostic phase recording.
- PairingView.swift supports manual peer entry and device-ID QR scanning. PairingQRCode.swift validates Syncthing device-ID QR data including checksums through the Go core.
- Diagnostics.swift persists bounded redacted session events and creates a shareable redacted JSON report.
- VaultConflictScanner.swift searches for preserved Syncthing conflict copies after sync.
- VaultSpikeRunner.swift verifies create/read/edit/rename/delete access using a temporary Markdown file.
- VaultAccessView.swift is the current dashboard and will be substantially redesigned.
- XcodeGen generates the Xcode project from app/project.yml.
